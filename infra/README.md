# NoteSnap — AWS Infrastructure

Single AWS CDK (TypeScript) stack that provisions the entire NoteSnap backend: Cognito auth, API Gateway, 6 Lambda functions, RDS PostgreSQL, and S3 — deployed to **eu-west-1**.

See the [root README](../README.md) and [../docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md) for diagrams and the full system picture. This file covers infra-specific dev/deploy workflow only.

## Stack

Everything lives in [`lib/infra-stack.ts`](lib/infra-stack.ts) — one `InfraStack`. Read the comments there directly; they document the *why* behind non-obvious choices (VPC subnet split, self-invoke IAM policy, Cognito pool recreation, secrets-via-runtime-fetch) inline, and [../docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md#key-engineering-decisions) summarizes the same decisions at a higher level.

## Prerequisites

- AWS account with the CDK bootstrapped in eu-west-1 (`npx cdk bootstrap`)
- AWS credentials configured (see the `signing-in-to-aws` guidance if using an org SSO setup)

## Commands

```bash
npm install
npm run build      # tsc type-check
npm run watch       # tsc -w
npm run test         # jest
npx cdk diff          # preview changes against the deployed stack
npx cdk deploy         # deploy
npx cdk synth            # emit the synthesized CloudFormation template
```

## Secrets — populate out of band, never in code

Three secrets must exist in Secrets Manager before the Lambdas will function correctly. **Never** put real values in CDK source, environment files, or chat — see the project's `CLAUDE.md` Secret Safety section.

```bash
# RDS credentials — auto-generated by the stack itself (DbCredentialsSecret), no action needed

# Gemini API key — placeholder secret is created by the stack; populate the real value:
aws secretsmanager put-secret-value \
  --secret-id notesnap/gemini/api-key \
  --secret-string '{"apiKey":"<your-key>"}'

# Google OAuth client secret — referenced by ARN in infra-stack.ts (GoogleOAuthClientSecret);
# create/populate it the same way if setting this up fresh in a new account:
aws secretsmanager create-secret \
  --name notesnap/google-oauth/client-secret \
  --secret-string '<your-google-oauth-client-secret>'
```

After creating the Google OAuth secret fresh, update the hardcoded secret ARN and Google OAuth client ID in `infra-stack.ts` (`GoogleOAuthClientSecret`, `GoogleIdentityProvider`) to match your own Google Cloud project.

## Post-deploy: Google OAuth redirect URI

`cdk deploy` prints a `GoogleOAuthRedirectUri` output — paste that exact value into Google Cloud Console → your OAuth client → Authorized redirect URIs before Google sign-in will work.

## Lambda functions

| File | Route | Purpose |
|---|---|---|
| `generate-notes.ts` | `POST /notes/generate` | Async: creates a `generating` row, self-invokes to call Gemini, writes the result |
| `list-notes.ts` | `GET /notes` | Metadata list for the current user |
| `get-note.ts` | `GET /notes/{id}` | Metadata + content (content is `null` until `status='ready'`) |
| `save-note-edit.ts` | `PUT /notes/{id}` | Overwrites note content, sets `edited=true` |
| `delete-note.ts` | `DELETE /notes/{id}` | Deletes the RDS row + S3 object |
| `delete-account.ts` | `DELETE /account` | GDPR erasure: RDS rows + S3 objects + Cognito user, in one request |
| `schema-migration.ts` | — | CloudFormation Custom Resource; applies `schema.sql` inside the VPC (RDS has no public route) |

Shared helpers live in `lambda/lib/` (`db.ts` — pooled Postgres client via RDS credentials secret, `s3.ts` — note content get/put, `http.ts` — response helpers).

## Schema changes

Edit `lambda/schema.sql`. Every statement must be safe to re-run (the migration Custom Resource re-applies it on every deploy where `SchemaVersion` changes) — use `if not exists` / `drop ... if exists` / conditional `pg_constraint` lookups rather than one-shot DDL. Bump the `SchemaVersion` property on the `SchemaMigrationResource` Custom Resource in `infra-stack.ts` to force a re-run even when CloudFormation wouldn't otherwise detect a change.
